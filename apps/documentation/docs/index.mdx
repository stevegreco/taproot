This design system provides a shared language for color, typography, spacing,
and component decisions. Its tokens are available as CSS custom properties and
structured JSON, so the same source of truth can support applications, design
tools, and automation.

## Token architecture

<Steps>
  <Step title="Primitives">
    Raw scales such as color ramps, spacing values, and type sizes. They define the available
    palette but carry no UI intent.
  </Step>
  <Step title="Semantic tokens">
    Intent-based aliases such as background, foreground, border, and status. Use these for component
    and product styling.
  </Step>
</Steps>

:::tip[Selection rule]
Use semantic tokens whenever they express the intended role. Use a primitive
only when no semantic contract fits.
:::
